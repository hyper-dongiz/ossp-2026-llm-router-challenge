`analysis/decision-trail.md`를 읽기 전에 이 문서를 보면 됩니다.
쉬운 것부터 어려운 것 순서입니다.

## 1. 과제의 기본

**모델 3개** — 답변을 만드는 AI 세 종류입니다. 문서에서는 이렇게 부릅니다.

| 정식 이름 | 이 문서에서 | 성격 |
|---|---|---|
| `ax31-light` | 싼 모델 | 가장 저렴. 짧게 답함 |
| `ax31` | 중간 모델 | |
| `axk1-think` | 비싼 추론 모델 | 가장 비쌈. 길게 답함 |

**라우터** — 문항마다 셋 중 하나를 고르는 프로그램. 우리가 만드는 것.
모델을 직접 부르지는 않고, "이 문항은 저 모델" 이라는 선택만 출력합니다.

**등급 (tier)** — 예산 한도가 다른 세 가지 평가 시나리오.

| 등급 | 예산 한도 | 최종 점수 가중치 |
|---|---:|---:|
| Fast | 1.25배 | **0.4** ← 가장 중요 |
| Balanced | 2.0배 | 0.3 |
| Premium | 4.0배 | 0.3 |

**비용비율 (budget ratio)** — 우리가 쓴 돈 ÷ 전부 싼 모델을 썼을 때의 돈.
1.0이면 싼 모델만 쓴 것과 같은 비용, 2.0이면 두 배 쓴 것.
이 값이 등급의 한도를 넘으면 **그 등급 점수는 전부 0**입니다. 부분 감점이 아닙니다.

**한도 소진율** — 비용비율 ÷ 한도. 99.6%면 한도를 거의 다 쓴 상태.

## 2. 예측에 관한 말

**특징 (feature)** — 프롬프트 글자를 숫자로 바꾼 것.
글자 수, 한글 비율, 숫자 밀도 등 14개 + 단어를 256칸에 흩뿌린 해시 값 256개 = 270개.

**해시 버킷** — 단어를 기계적으로 0~255번 칸 중 하나에 넣는 방식.
사전이 없어서 처음 본 단어도 처리됩니다. 대신 무관한 단어가 같은 칸에 섞입니다
(연습 데이터의 서로 다른 단어 4만 7천 개가 256칸을 공유 → 칸당 평균 185개).

**회귀 (regression)** — 특징에 곱할 숫자(계수)를 데이터에서 찾아,
`예측 = 절편 + 계수₁×특징₁ + … ` 형태로 값을 맞히는 것.

**계수 (coefficient)** — 위 식의 곱하는 숫자들. 학습으로 정합니다.

**ridge (릿지)** — 회귀의 한 종류. 계수가 너무 커지지 않게 벌점을 붙입니다.
공개 기준 구현이 쓰는 방식이고, 닫힌 공식으로 한 번에 풀립니다.

**편향 (bias)** — 여기서는 **총합**이 체계적으로 틀어진 정도를 말합니다.
`실제 총합 ÷ 예측 총합 − 1`. +52%면 실제가 예측보다 52% 많다는 뜻.

> **왜 총합인가**: 예산은 문항 하나하나가 아니라 880문항의 **합계**로 판정됩니다.
> 그래서 개별 문항을 잘 맞히는 것보다 합계가 안 틀어지는 게 중요합니다.
> 개별 오차는 서로 상쇄되지만, 한쪽으로 쏠린 오차는 그대로 누적됩니다.

## 3. 우리가 찾은 버그에 관한 말

**로그 (log)** — 큰 수와 작은 수의 차이를 압축하는 변환.
답변 길이가 20토큰에서 13만 토큰까지 벌어져 있어 그대로 다루기 어렵습니다.
그래서 로그를 씌워 순하게 만든 뒤 회귀합니다.

**되돌림 편향 (retransformation bias)** — **이 프로젝트의 핵심 버그.**

로그를 씌워 회귀하면 "로그의 평균"을 얻습니다. 그걸 지수(`exp`)로 되돌리면
원래 값의 **평균이 아니라 중앙값에 가까운 값**이 나옵니다.

비유: 동네 소득이 대부분 3천만 원인데 몇 명이 100억 원이면
중앙값은 3천만, 평균은 5억입니다. **세금 총액을 알고 싶으면 평균이 필요한데
중앙값을 쓴 셈**입니다. 그래서 총합이 크게 모자랍니다.

측정값: 싼 모델 18.2% / 중간 11.4% / **비싼 추론 모델 52.2%** 과소추정.

**Duan smearing (스미어링)** — 위 버그의 교과서 해법 (1983년).
잔차(실제÷예측)의 평균을 보정계수로 구해 예측에 곱합니다. 구현 5줄.
싼·중간 모델은 해결됐고 비싼 모델은 15.2%가 남았습니다.

**잔차 (residual)** — 실제값과 예측값의 차이(또는 비).

**이분산 (heteroscedasticity)** — 오차의 크기가 상황마다 다른 것.
문항 종류에 따라 예측이 더 많이/적게 틀리는 현상.

**꼬리 (tail)** — 분포의 극단 쪽. "무거운 꼬리"는 아주 큰 값이 드물지 않게 나오는 것.
우리 데이터: **880문항 중 상위 1%(9문항)가 전체 비용의 17%**를 씁니다.
이래서 평균 기반 보정이 안정되지 않습니다.

## 4. 해법에 관한 말

**분위수 (quantile)** — "아래쪽 몇 %에 해당하는 값".
90% 분위수는 "전체의 90%가 이 값보다 작다"는 지점입니다. 중앙값은 50% 분위수.

**분위수 회귀 (quantile regression)** — 평균이 아니라 특정 분위수를 맞히는 회귀.

**왜 이게 답인가** — 두 가지 이유입니다.

1. **분위수는 로그를 씌워도 순서가 유지됩니다.**
   로그 공간의 90% 분위수를 지수로 되돌리면 원래 단위의 정확한 90% 분위수입니다.
   평균은 이 성질이 없습니다. → **되돌림 편향이 원천적으로 없어집니다.** 보정 불필요.
2. **예산 판정에 필요한 건 애초에 평균이 아니라 상한입니다.**
   "이 정도면 넘지 않는다"는 값이 필요하고, 그게 상위 분위수입니다.

**tau (타우)** — 어느 분위수를 맞힐지 정하는 값. 0.9면 90% 분위수.

**pinball 손실 (check 손실)** — 분위수 회귀를 학습할 때 쓰는 손실 함수.
예측이 낮을 때와 높을 때 벌점을 다르게 줍니다. 그래서 평균이 아닌 분위수로 수렴합니다.

**교정 (calibration)** — 분위수 예측이 약속을 지키는지 확인하는 것.
tau=0.9로 예측했으면 실제값이 그걸 넘는 비율이 **10%**여야 합니다.
실측: 학습 데이터에서 9.9~10.3%(정확), 검증 데이터에서 12.7~14.8%(약간 낙관적).

## 5. 검증에 관한 말

**보정셋 / 홀드아웃 (calibration / holdout)** — 연습 데이터를 반으로 나눠,
한쪽으로 값을 정하고 **다른 쪽은 손대지 않고 남겨** 채점에 씁니다.
같은 데이터로 정하고 같은 데이터로 채점하면 실력을 알 수 없습니다.

**in-sample (인샘플)** — 값을 정할 때 쓴 데이터로 성능도 보고하는 것. **하면 안 되는 일.**
공개 기준 구현이 이걸 했고, 그래서 실제 채점에서 터졌습니다.

**층화 분할 (stratified split)** — 무작위로 반씩 나누지 않고, 길이·어휘 같은
기준으로 정렬해 **한쪽에 없는 종류를 다른 쪽에 몰아주는** 분할.
무작위로 나누면 양쪽 구성이 같아져서 "채점 데이터가 다르게 생겼을 위험"을 못 봅니다.
공식 과제 페이지가 "비공개 평가의 데이터 구성과 분포는 공개하지 않는다"고 했으므로
이 위험은 가능성이 아니라 **의도된 조건**입니다.

**일반화 갭 (generalization gap)** — 보정셋에서 본 값과 홀드아웃에서 본 값의 차이.
우리 측정: 최악의 경우 Premium 비용비율이 한도의 **132%** 까지 갔습니다.

**안전계수 (safety ratio)** — 예산을 일부러 다 쓰지 않고 남기는 비율.
0.925면 한도의 92.5%까지만 쓰겠다는 뜻. 예측이 틀릴 것에 대비한 보험입니다.

**기대점수** — 예산을 넘긴 경우를 0점으로 계산한 평균 점수.
실제 채점 규칙이 그렇기 때문에, 초과를 무시한 평균은 의미가 없습니다.

## 6. 역할 분담 용어

| 표기 | 담당 | 하는 일 |
|---|---|---|
| A1 | 특징 추출 | 프롬프트 글자 → 숫자 270개 |
| A2 | 배분 | 예상 점수·비용을 받아 예산 안에서 모델 선택 |
| B | 런타임 | 컨테이너가 시간 안에 유효한 결과를 내게 함 |
| **C** | **평가·비용추정** | **비용 예측 + 검증 체계** ← 우리 |

**배낭 문제 (knapsack)** — 무게 한도가 있을 때 가치를 최대로 담는 문제.
우리 상황: 예산 한도 안에서 점수를 최대로 만드는 모델 선택.

**라그랑주 완화 / 이분탐색** — 배분기가 쓰는 계산 방법.
"돈 1원의 가치(λ)"를 정해놓고 각 문항에서 `점수 − λ×비용`이 최대인 모델을 고릅니다.
합계가 예산을 넘으면 λ를 올려 다시 계산합니다(80회 이분탐색).
문항 순서에 의존하지 않아 규칙에 맞습니다.
